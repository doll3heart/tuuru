## 反模式判定

**视觉评估：明显有 AI 批量生成感。** 十二款组件使用几乎相同的横向矩形、三层文字和右侧箭头，只更换边框、圆角、底色或伪物件装饰。所谓胶片、信封、唱片、拍立得并没有改变信息构图，因此用户看到的是“一张卡片的十一种 CSS 滤镜”。商店又把组件塞进另一层卡片，形成典型的嵌套卡片墙。

**确定性扫描：** `detect.mjs --json reader/reader.js` 返回 0 项。这不是视觉质量背书；扫描目标是生成标记的 JavaScript，无法判断构图、物件感和美术方向。没有误报。

**可视化覆盖：** 检测评审的独立浏览器后端不可用，因此没有可靠的人眼覆盖层。它以 HTTP 200、源码位置、模块渲染计数和 CSS 声明作为降级证据；未声称存在浏览器覆盖层。

## 整体印象

流程逻辑已经比旧勾选列表清楚：能看、能加、能撤、能换。但“组件商店”制造了逛店期待，实际商品却像后台信息卡，情绪落差反而更大。最大机会不是继续丰富皮肤，而是先建立 4—5 种真正不同的组件原型，再让内容适配原型。

## 做得好的部分

- 商店预览复用真实运行时渲染，避免“商店图很好看，添加后变样”。
- 空状态、添加反馈、已添加管理和即时手机预览形成完整闭环。
- 静态预览使用 `div`，检测证据确认生成路径没有按钮嵌套；桌面双列、手机单列的基础响应式方向正确。

## 优先问题

### [P1] 十二种内容共用同一张横向信息卡骨架

**为什么重要：** 用户无法凭轮廓产生偏好，组件也不能成为桌面的装饰主体。

**修复：** 废弃“所有内容 × 所有皮肤”的排列组合。先设计真正不同的原型：大号日历、竖向拍立得、圆形唱片机、横向消息胶囊、自由排版便签、人物状态头像组。每个原型拥有自己的比例、排版和交互，不只是边框。

**建议命令：** `$impeccable shape`

### [P1] 商店卡片里再套组件卡片，预览被压成缩略图

**为什么重要：** 用户是在看商品，却要透过两层边框和大量说明文字猜商品；装饰细节和比例优势全部被缩没。

**修复：** 商店改成沉浸式样板：组件预览占卡片 70% 以上，名称和“添加”只做底部轻量工具条。已添加区单独管理，不与商店同时长列表展示。

**建议命令：** `$impeccable layout`

### [P1] 十二个相似选项一次铺开，没有精选和分类

**为什么重要：** 超过工作记忆容量，用户会快速扫过而不是认真选择；相似度又放大了选择疲劳。

**修复：** 首屏只给“今日精选 / 角色互动 / 阅读进度 / 纪念收藏”四个入口，每类 2—4 款；默认推荐 3 款完成度最高的组件。

**建议命令：** `$impeccable distill`

### [P2] 色彩统一，却没有统一的美术方向

**为什么重要：** 粉灰变量把所有物件染成同一种雾蒙蒙的后台皮肤，既不真实也不鲜明。

**修复：** 选择明确艺术方向并限定材质语言。颜色应该服务于纸张、塑料、像素屏或印刷物，而不是让所有组件共享一组浅粉底色。

**建议命令：** `$impeccable colorize`

### [P2] 手机端部分控制低于舒适触控尺寸

**为什么重要：** 静态证据显示添加与宽度按钮最小高度 36px、换外观 38px，低于 44px 触控基准。

**修复：** 手机端统一提升到至少 44px，并减少同一区域并排的小按钮数量。

**建议命令：** `$impeccable adapt`

## 用户视角风险

**Jordan（第一次使用）：** 打开商店后同时看到十二个长得相近的选项，不知道“内容类型”和“外观皮肤”的区别。她会随便点一个，而不是因为喜欢而添加。

**Casey（手机单手操作）：** 单列商店需要长距离滚动，36—38px 控制偏小；商店、已添加区和统一配色连续堆叠，返回后很难快速定位。

**Sam（键盘/低视力用户）：** 状态与标签基础较好，但十一种样式墙缺少更高层分类；视觉差异主要依赖细小边框和浅色材质，低视力下区别进一步消失。

## 认知负荷

- 单一焦点：失败，已添加管理和商店商品同时竞争注意力。
- 分块：失败，十二项商店和十一项样式墙超过舒适数量。
- 分组：部分通过，有商店/已添加区，但商品内部仍高度同质。
- 视觉层级：失败，预览、说明、卡片边界和按钮权重接近。
- 一次一件事：失败，浏览、管理、配色在同一展开区连续出现。
- 最少选择：失败，单次决策可见 12 或 11 个选项。
- 工作记忆：通过，真实预览减少跨屏记忆。
- 渐进披露：部分通过，商店与换肤可展开，但展开后没有继续分层。

整体为高认知负荷，主要来自相似选项数量，而不是功能步骤。

## 情绪旅程

“组件商店”这个名称建立了发现漂亮小物的期待；进入后先看到大量相似卡片，形成明显情绪低谷。添加成功的即时预览是目前唯一的小高潮，但组件本体缺乏收藏欲，无法形成结束时的满足感。

## 次要观察

- 右侧箭头几乎出现在每款组件中，让它们更像导航列表而不是桌面物件。
- 元信息、标题、详情三行结构过于固定，短内容也被迫填满模板。
- CSS 伪物件细节在商店缩略比例下不可读，只留下不规整的边缘。
- 移除、排序、换肤和宽度控制全压在组件附近，管理态比欣赏态更强。
